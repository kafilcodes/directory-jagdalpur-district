## 🌟 Overview

**Jagdalpur Business Directory** is a cutting-edge digital platform designed to bridge the gap between local businesses and residents in Jagdalpur, Chhattisgarh. Built with modern web technologies and best practices, this platform serves as the **official business directory** for the district administration.

### 🎯 Mission

> *To empower local businesses with digital visibility, provide residents with instant access to trusted services, and support the local economy through enhanced connectivity.*

### 🏛️ Ownership

This platform is **privately owned** and operated by the **Jagdalpur District Administration** as a public utility service.

## 🏗️ Architecture

### **🎨 Design Philosophy**

This project follows the **"Aggregated Sharded Index with Denormalized Analytics"** architecture for maximum performance and minimal costs.

```
┌─────────────────────────────────────────────────────────────┐
│                     CLIENT (Next.js App)                    │
│  ┌─────────────┐  ┌──────────────┐  ┌──────────────┐      │
│  │   Search    │  │   Chatbot    │  │   Listings   │      │
│  │   Engine    │  │   (Gemini)   │  │   Browser    │      │
│  └──────┬──────┘  └──────┬───────┘  └──────┬───────┘      │
└─────────┼─────────────────┼──────────────────┼──────────────┘
          │                 │                  │
          ▼                 ▼                  ▼
┌─────────────────────────────────────────────────────────────┐
│                   API ROUTES (Next.js)                      │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
│  │ /search  │  │ /chatbot │  │ /listing │  │ /payment │  │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘  └────┬─────┘  │
└───────┼─────────────┼─────────────┼─────────────┼─────────┘
        │             │             │             │
        ▼             ▼             ▼             ▼
┌─────────────────────────────────────────────────────────────┐
│                  FIREBASE FIRESTORE                         │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
│  │ listings │  │  search  │  │   users  │  │ payments │  │
│  │(300 docs)│  │(26 docs) │  │(500 docs)│  │(100 docs)│  │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘  │
│                                                             │
│  Sharded Index: index_a, index_b, ... index_z               │
│  Each shard: ~12 docs (26 letters × 12 = 312 docs/month)   │
└─────────────────────────────────────────────────────────────┘
```

### **🔥 Firestore Collections**

| Collection | Purpose | Avg Size | Read Frequency |
|------------|---------|----------|----------------|
| `listings` | Business data | 300 docs | High (cached) |
| `search` | Sharded index | 26 docs | Very High |
| `users` | User profiles | 500 docs | Medium |
| `payments` | Transactions | 100 docs | Low |
| `analytics` | Denormalized stats | 300 docs | Low |

### **⚡ Performance Optimizations**

- ✅ **Sharded Search Index** - Sub-50ms query times
- ✅ **Denormalized Analytics** - Zero expensive aggregations
- ✅ **Edge Caching** - Vercel Edge Network
- ✅ **Image Optimization** - Next.js Image component
- ✅ **Code Splitting** - Dynamic imports
- ✅ **Lazy Loading** - Intersection Observer API
- ✅ **Memoization** - React.memo & useMemo
- ✅ **Database Connection Pooling** - Firebase Admin SDK

- **Node.js** 18.17 or higher

- **Firebase** project with Firestore enabled
- **Razorpay** account (for payments)

### **⚙️ Installation**

```bash
# 1. Clone the repository
git clone https://github.com/yourusername/dhamtari-directory.git

# 2. Install dependencies
npm install

yarn install

pnpm install
```

## 🌍 Multi-City Deployment

This platform is designed to support **multiple cities** using a **single Firebase project** with separate Firestore databases.

### **🎯 Architecture for Multi-City**

```
Single Firebase Project
├── Firestore Database: dhamtaridirectory (Jagdalpur)
├── Firestore Database: raipurdirectory (Raipur)
├── Firestore Database: bilaspurdirectory (Bilaspur)
└── Shared: Auth, Storage, Functions
```

### **📝 Steps to Deploy for a New City**

#### **1️⃣ Create New Firestore Database**

```bash
# In Firebase Console
1. Go to Firestore Database
2. Click "Create Database"
3. Choose Database ID: "raipurdirectory"
4. Select Region: asia-south1 (Mumbai)
5. Start in Production Mode
6. Copy Security Rules from existing database
```

#### **2️⃣ Update Environment Variables**

Only update these variables for the new city:

```bash
# Database ID (CRITICAL!)
FIREBASE_DATABASE_ID=raipurdirectory
NEXT_PUBLIC_FIREBASE_DATABASE_ID=raipurdirectory

# City Branding
NEXT_PUBLIC_APP_NAME=Dial Raipur
NEXT_PUBLIC_CITY_NAME=Raipur
NEXT_PUBLIC_STATE_NAME=Chhattisgarh
NEXT_PUBLIC_CITY_PIN_CODE=492001

# Location
NEXT_PUBLIC_MAP_CENTER_LAT=21.2514
NEXT_PUBLIC_MAP_CENTER_LNG=81.6296
NEXT_PUBLIC_MIN_LAT=21.0
NEXT_PUBLIC_MAX_LAT=21.5
NEXT_PUBLIC_MIN_LNG=81.3
NEXT_PUBLIC_MAX_LNG=81.9

# Contact & Branding
NEXT_PUBLIC_SITE_URL=https://raipur.directory
NEXT_PUBLIC_CONTACT_EMAIL=raipur@example.com
NEXT_PUBLIC_CONTACT_PHONE=+91-1234567890
NEXT_PUBLIC_COPYRIGHT_HOLDER=Raipur District Administration
```

#### **3️⃣ Deploy to New Domain**

```bash
# Option A: Deploy to subdomain
vercel --prod
# Set domain: raipur.directory

# Option B: Deploy to separate project
vercel --prod --project raipur-directory
```

#### **4️⃣ Initialize Database Collections**

```bash
# Run initialization script (if available)
npm run init-db

# Or manually create collections:
# - listings
# - users
# - search (with 26 documents: index_a to index_z)
# - payments
# - analytics
```

### **🔄 Keeping Firebase Credentials Same**

✅ **Keep these SAME for all cities:**
- NEXT_PUBLIC_FIREBASE_API_KEY
- NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN
- NEXT_PUBLIC_FIREBASE_PROJECT_ID
- FIREBASE_ADMIN_CLIENT_EMAIL
- FIREBASE_ADMIN_PRIVATE_KEY
- RAZORPAY credentials
- GEMINI_API_KEY

❌ **Change these for each city:**
- FIREBASE_DATABASE_ID ← **MOST IMPORTANT**
- All NEXT_PUBLIC_CITY_* variables
- Map coordinates
- Contact information
- Site URL

## 🔍 Search & Ranking System

### **🎯 Search Architecture**

The platform uses a **custom-built, hyper-optimized search system** designed for sub-50ms query times with zero external dependencies.

```
User Query: "electronics shop"
     │
     ▼
┌────────────────────────────────────────┐
│  1. QUERY PROCESSING                   │
│  ├─ Typo correction (eletronics→electronics)
│  ├─ Category detection (electronics)  │
│  └─ Term extraction (NLP)             │
└────────────┬───────────────────────────┘
             │
             ▼
┌────────────────────────────────────────┐
│  2. SMART MATCHING (Priority-based)    │
│  ├─ Tier 1: Exact category match (100)│
│  ├─ Tier 2: Exact name match (100)    │
│  ├─ Tier 3: Partial category (80)     │
│  ├─ Tier 4: Name contains (70)        │
│  ├─ Tier 5: Tags match (50)           │
│  └─ Tier 6: Description (20)          │
└────────────┬───────────────────────────┘
             │
             ▼
┌────────────────────────────────────────┐
│  3. RANKING ALGORITHM                  │
│  ├─ Match score (0-100)               │
│  ├─ Popularity (views/clicks)         │
│  ├─ Recency (last updated)            │
│  └─ Featured status (boosted)         │
└────────────┬───────────────────────────┘
             │
             ▼
┌────────────────────────────────────────┐
│  4. RESULTS DELIVERY                   │
│  └─ Top N results (<50ms)             │
└────────────────────────────────────────┘
```

### **🧠 NLP Features**

- **Typo Tolerance**: `resturant` → `restaurant`
- **Synonym Expansion**: `doctor` → `doctor, clinic, medical`
- **Category Intelligence**: Detects when user searches category vs. business name
- **Context Awareness**: Uses conversation history for better results

### **📊 Ranking Factors**

| Factor | Weight | Example |
|--------|--------|---------|
| Exact Match | 100 | "Deepak Electronics" = "deepak electronics" |
| Category Match | 80 | category: "restaurant" = "restaurant" |
| Name Contains | 70 | "Gupta" in "Gupta Electronics" |
| Tags Match | 50 | "fast food" in tags |
| Description | 20 | "pizza" in description |
| Views/Clicks | 0-20 | Popularity boost |
| Featured Status | +30 | Paid promotion |

### **⚡ Performance**

- **Average Query Time**: 35-50ms
- **Search Index Size**: 26 documents (sharded A-Z)
- **Cache Hit Rate**: 85%+ (Edge Network)

```typescript
  PUBLIC = 'public',        // Browse only

  ADMIN = 'admin'           // Full access
}
```

### **🛡️ Security Features**

- ✅ **CSRF Protection** - Token-based validation
- ✅ **Rate Limiting** - API throttling (100 req/min)
- ✅ **Input Validation** - Zod schemas
- ✅ **XSS Prevention** - Sanitized outputs
- ✅ **SQL Injection** - N/A (NoSQL database)
- ✅ **Firestore Rules** - Database-level security

### **🔐 Firestore Security Rules**

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Public read, authenticated write
    match /listings/{listingId} {
      allow read: if true;
      allow create: if request.auth != null;
      allow update, delete: if request.auth.uid == resource.data.ownerId;
    }
    
    // Admin-only
    match /users/{userId} {
      allow read: if request.auth.uid == userId;
      allow write: if request.auth.token.admin == true;
    }
  }
}
```
